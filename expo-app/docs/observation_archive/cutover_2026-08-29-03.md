## Confirmed cause

The Mobile classifier was correct and SAP contained valid future fixtures. The
Mobile BFF current-match query sorted unfinished rows by date descending and
time ascending but fetched only the first 50 rows before applying the active
deviation filter. Parked and out-of-scope early fixtures consumed that window,
so active fixtures later in the day never reached either the live or upcoming
Mobile lists. The unchanged pilot runtime consequently returned one `LIVE` row
and no `NOT_STARTED` rows even though the wider SAP read contained upcoming
fixtures.

## Implementation

`zbet-cap/srv/mobile-bff/provider.js` now uses a dedicated bounded
`MAX_MATCH_ROWS = 200` window for current-match and match-insight list reads.
The downstream response limit remains 50, and the limits for live rates,
single-match reads, Super decisions and Toto data are unchanged.

`zbet-cap/test/mobile-bff-provider.test.js` can emulate the upstream `$top`
constraint and includes a regression with 50 parked rows followed by an active
upcoming fixture. The fixture at row 51 must remain visible as `NOT_STARTED`.
