## Decision contract

For each live or half-time match, the representative BTB decision is selected
from non-void Super Log rows in this order:

1. highest numeric `rating` / BTB star count;
2. newest `created_at` when ratings are equal;
3. newest decision minute;
4. deterministic market and decision-reason ordering.

Model score is neither a ranking key nor an eligibility filter. A representative
decision may therefore have a null model score. Selection, rating, minute,
reason, model score, confidence and selection rate remain atomic fields from the
winning Super Log row; current rate is read for that row's selected market.
Historical timeline rows remain chronological.

## Implementation

`zbet-cap/srv/mobile-bff/provider.js` now requests non-void Super Log rows in
rating-first/newest-first order and repeats the same deterministic order in the
defensive in-memory selector. Null model scores are retained. The shared
representative object continues to feed both Live summaries and Match Detail.

`zbet-cap/test/mobile-bff-provider.test.js` covers:

- an older higher-rated row beating a newer lower-rated row even when its model
  score is lower;
- equal ratings selecting the newest row;
- a void five-star row being ignored;
- an unscored row remaining eligible;
- list/detail field parity, selected-market current rate and existing fallback;
- downstream star-bucket counts following the newly eligible representative.

`zbet-mobile/expo-app/src/components/MatchTimelineCard.tsx` removes the detached
left-side rating stars. The outlined center marker now expands horizontally and
renders the full 1–5 star value. `super-rating-marker.ts` supplies one clamped
star count and matching `BTB rating n/5` accessibility label; its unit test
covers all five ratings and invalid bounds.
