## Decision contract

For a live match, the representative BTB choice is the non-void Super Log
decision with the highest numeric `final_score` (the published model score).
Equal scores resolve by newest `created_at`, then elapsed minute, market name,
rating and reason. Rows without a numeric score are not candidates. If no scored
decision exists, the existing current-match fallback remains unchanged.

The representative row is atomic: selection, rating, decision minute, reason,
model score, confidence and selection rate come from the same Super Log record.
The current rate is then read for that record's market. Historical timeline rows
are unchanged and remain chronological.

## Implementation

`zbet-cap/srv/mobile-bff/provider.js` now performs one bounded Super Log lookup
for each live/half-time match, ordered by the contract above. It excludes
`VOID`/`VOIDED` and null scores at the source and repeats the defensive checks in
the BFF. The selected market is also used for the current-rate lookup.

`zbet-cap/srv/mobile-bff/sap-mappers.js` maps the representative decision once
and supplies it to both match summary and match detail. The existing Mobile DTO
shape did not change, so `MatchCard`, Match Detail hero, `Karar özeti`, odds,
trend and accessibility text consume the corrected values without a Mobile UI
patch.

Regression coverage proves:

- an older high-score decision outranks a newer low-score decision;
- match list and match detail receive the same decision fields;
- current rate follows the selected decision's market;
- equal scores choose the newest decision;
- void and unscored rows cannot win;
- no scored Super row preserves the existing current-match fallback.
