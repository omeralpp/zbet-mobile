# BTB Mobile Next — 2026-08-18 cutover closure

Live Context v2 gerçek olay yolu. SAP köprüsü aktive edildi, uçtan uca
doğrulandı ve runtime açıldı. Mobile kaynak değişikliği olmadı; doğrulanmış APK
baseline'ı değişmedi.

Durum: `LIVE_CONTEXT_V2_ACCEPTED`

## Sağlayıcı erişimi — kalıcı bulgu

Bilyoner genel olarak erişilemez **değildir**. Ayrım istemci istek profilindedir:

```text
SAP gömülü HTTP istemcisi  -> çalışıyor  (üretimde oran/skor/istatistik/bülten)
curl, aynı makine          -> 400 users-api login kapısı
Node fetch / node:https    -> 400 users-api login kapısı
```

2026-08-18 ölçümü teşhisi güçlendirdi: `curl` artık yalnız hedef uçta değil,
SAP'ın üretimde başarıyla kullandığı uçlarda da (`gamelist/all/v1`,
`livestatistics`, `standing`) reddediliyor; buna karşılık SAP güncel maç gününü
Bilyoner'den yüklemişti. `curl` düz `curl/` user-agent gönderirken reddedildiği
için fark **header kaynaklı olamaz**.

Bu, önceki oturumdaki "curl çalışıyor, Node çalışmıyor" çerçevesinin bir
zamanlama tesadüfü olduğunu gösterdi. Kalıcı olgu: **SAP çalışıyor, bu makinedeki
doğrudan istemciler kapıda.** Çözüm, çalışan istemciyi ödünç almaktır — TLS
parmak izi taklidi değil. Çerez kopyalama, oturum tekrarı, giriş otomasyonu ve
parmak izi taklidi yapılmadı ve kapsam dışıdır.

## SAP köprüsü — aktive edildi

Onaylanan kapsam, tamamı: `ZBET_CL_PROVIDER_BRIDGE` sınıfı,
`/sap/bc/zbet/provider/detail` SICF düğümü ve köprünün TVARVC özellik/kimlik
yapılandırması. **DDIC yok, tablo yok, kalıcılık yok, model değişikliği yok.**

Köprü bir alan katmanı değildir: tek bir dondurulmuş sağlayıcı yolunu iletir ve
sağlayıcının kendi baytlarını döndürür. Bütün Live Context normalizasyonu, tek
tanımın bulunduğu yer olan BFF'te kalır.

Güvenlik özellikleri: çağıran URL seçemez — yalnız sayısal event id, derleme
zamanı sabitine yerleştirilir; `INSERT/UPDATE/COMMIT` yok; TVARVC anahtarı
olmadan kapalı; token SHA-256 ile doğrulanır; yanıt boyutu sınırlıdır. Taşıma
`zbet_cl_main=>get_instance( )->get_rss( )`, **değiştirilmeden** yeniden
kullanıldı.

Aktivasyon sırası bilinçli olarak parçalıydı: önce sınıf/SICF/konfigürasyon,
sonra tek sınırlı SAP kanıtı, sonra tek BFF entegrasyon kanıtı, ancak hepsi
geçtikten sonra runtime.

## Kanıtlar

**E — tek sınırlı SAP kanıtı** (event 3059015):

```text
köprü durumu   : HTTP 200
sağlayıcı gövde: {"status":{"code":200,"message":"Success"}}
sınıflandırma  : PROVIDER_PAYLOAD — login kapısı değil
```

İlk çağrı `401 Missing or invalid x-btb-bridge-token` döndü; bu köprünün kendi
JSON hatasıydı ve sınıfın aktif, SICF'in yönlendirdiği, özellik anahtarının
açık (kapalı olsa 503) ve kimlik doğrulamanın **kapalı biçimde başarısız**
olduğunu kanıtladı. Neden token'ın kendisi değil, çağıran süreçte boş
gönderilmesiydi; 401 `get_rss` öncesinde kesildiği için sağlayıcıya istek
gitmedi.

**F — gerçek sağlayıcı sözlüğü**:

```text
GOAL : goalType, scorerName, assistPlayerName, homeScore/awayScore,
       minute, minuteDisplay, side, period      (v2'nin ihtiyacı olan her alan)
CARD : YELLOW_CARD x4 — başka kart değeri yok
```

Canlı payload kayıtlı fixture ile birebir aynıydı (21 feed: 3 GOAL, 4 CARD,
12 SUBS, 2 STATUS; betradarId 71778720), yani mevcut testler gerçek sözleşmeyi
kapsıyor. **Gerçek kırmızı kart hiç gözlenmedi.**

**G — BFF üzerinden köprü**:

```text
schemaVersion   btb.live-context.v2     availability OK
timeline        3 olay, kinds {"GOAL":3}
   1' GOAL HOME Calafiori, Riccardo 1-0 [FIRST_HALF]
  28' GOAL HOME Havertz, Kai        2-0 [FIRST_HALF]
  48' GOAL HOME Odegaard, Martin    3-0 [SECOND_HALF]
excludedByScope {"YELLOW_CARD":4,"STATUS_MARKER":2,"SUBSTITUTION":12}
unclassifiedCardValues []   unknownFeedTypes []
cache 1./2.     MISS / HIT     upstream çağrı: 1     408 ms / 0 ms
```

İlk sızıntı taraması `SUBSTITUTION` ve `YELLOW` işaretledi; bunlar **kendi fazla
geniş kontrolümün yanlış pozitifleriydi** — kelimeler yalnız
`diagnostics.excludedByScope` sayaçlarında geçiyor. Timeline'a özgü yeniden
kontrol on bağımsız iddiada da geçti: yalnız değişiklikte/sarı kartta geçen
oyuncuların (Eze, Grealish, Gvardiol, Foden) hiçbiri yayımlanan timeline'a
ulaşmıyor. Çıktıda token, parola veya authorization header yok.

**H — runtime**: canlı route uçtan uca `HTTP 200`, 2388 ms (soğuk), v2, 3 gerçek
gol, `lineups` alanı yok.

Not: BFF yeniden başlatması ilk denemede `-AuthMode pilot` olmadan yapıldığı için
4004 dinleyicisiz kaldı; zamanlanmış görevin kendi argümanları okunarak
`ensure-mobile-bff.ps1 -Port 4004 -AuthMode pilot` ile geri getirildi. Sebep
bendeydi ve düzeltme artık görevin başlatma biçimiyle aynı.

## Kabul

```text
REAL_GOAL_VALIDATION     = PHYSICAL_PASS
REAL_RED_CARD_VALIDATION = OWNER_ACCEPTED_PENDING_NATURAL_OBSERVATION
```

Gerçek GOAL olayları fiziksel Xiaomi doğrulamasında görüldü. Kırmızı kart
uygulaması sahip tarafından **doğrulanmış sözleşme, normalizer semantiği ve
otomatik testler** temelinde kabul edildi. **Gerçek bir kırmızı kartın fiziksel
olarak gözlendiği iddia edilmemektedir.** Doğal bir kırmızı kart yalnız
gözlemsel doğrulamadır, release engeli değildir; ileride bir sorun ortaya
çıkarsa yeni defect açılır.

Kırmızı kart semantiği (değiştirilmedi):

```text
bilinen düz kırmızı            -> RED_CARD / DIRECT_RED
bilinen ikinci sarıdan kırmızı -> RED_CARD / SECOND_YELLOW_RED
ihraç kanıtlı, alt tip yok     -> RED_CARD / UNKNOWN
sıradan sarı                   -> yayımlanmaz (YELLOW_CARD)
diğer her kart değeri          -> yayımlanmaz (UNCLASSIFIED_CARD)
```

Tanınmayan kart ihraç kanıtı sayılmaz; yanlış-pozitif kırmızı bu modülün
yapabileceği en kötü hatadır.
